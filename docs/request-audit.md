# 控制端请求拒绝审计

VIT-132 补齐私有 `privateService` 与内存开发 `controlService` 的应用层请求拒绝记录。它与既有 `authorize()` 检查记录分开，不新增审计读取 HTTP API、权限、角色或真实配置。没有 UI、Worker 事件协议或运行恢复流程变更。

## 范围与语义

进入 Node HTTP request 回调、尚未发送响应且连接仍可响应的失败，统一经过受控错误边界。涵盖缺失／无效／到期身份、JSON 内容类型／格式／大小、身份冒用、授权、租约、事件协议、未知路由，以及应用内部异常。已被 Node HTTP 解析器接受但无法构造 URL 的 request-target 返回受控 400，不再导致同步未捕获异常。

不记录成功请求，也不把成功的权限检查当成业务成功。每条请求拒绝独立于业务快照和授权检查审计；其中 `status` 是触发审计的原始拒绝状态，**不是业务回滚证明，也不保证等于客户端最终收到的状态**。若该条审计自身落盘失败，最终响应会被覆盖为 503 `request_audit_persistence_failed`。例如原本的 401 会留在待写记录中，而客户端收到 503。

已发送响应后的异常、已断开的连接、Node HTTP 解析器之前的拒绝和其他网络日志不在范围内。已提交动作不能因为响应丢失而被称为回滚；本功能不重放业务、模型调用或外部动作，也不伪造停止证据。

## 固定记录与隐私

每条仅有七个字段：

| 字段 | 来源 |
| --- | --- |
| `requestId` | 服务器为该请求生成的 UUID，不读取客户端 request ID |
| `at` | 服务器时钟，毫秒 Unix 时间 |
| `method` | 标准 HTTP 方法白名单，其他值统一 `OTHER` |
| `route` | 固定类型，如 `messages`、`message_edit`、`run_cancel`、`worker_events`；未知为 `unknown` |
| `actorId` | 成功认证得到的成员 ID；缺失／无效／到期认证统一为 `null`，不从请求体或任意 token 推断 |
| `status` | 原始拒绝状态，400–599 |
| `category` | 固定类别白名单，不保存任意 `ApiError.code` |

类别包括认证、内容类型、JSON 解析、大小、冒用、授权、租约、协议、无效请求、未找到、冲突、容量、存储和内部错误。细节未知时使用受控类别，不猜测拒绝原因。

**不记录** token 或其 hash、header、query、原始 URL／path、动态 message/run/lease/instance/session ID、body、消息正文、原始错误文本、stack 或客户端文件路径。静态资源统一 `web_asset`，动态路由仅返回固定类型。未知路由不能把攻击者输入变成持久化内容。重启读取时重新校验并只投影这七个字段。

审计不是跨系统全量日志，也不是防篡改签名账本。服务器生成的 request ID 当前只用于内部记录，不添加公开关联或读取接口。

## 有界、持久化与故障

- 请求账本的内存、待写记录和私有数据库都仅保留最近 1000 条。没有异步无界队列；超过上限会淘汰最旧记录，包括尚未写入的旧记录。
- 私有模式使用同库独立 `request_rejection_audit` 表，一个有界 JSON 行；独立 SQLite 原子写入，不受业务快照事务回滚影响。首次拒绝即使还没有业务快照，也能跨重启保留。
- 开发模式仅在进程内保留，不宣称重启持久化。既有授权检查审计的三处正常写入也立即截到 1000，避免开发入口授权拒绝洪泛使旧数组无限增长；权限判定与记录 schema 不变。
- 请求审计写入失败时，当前请求返回明确 503，原始拒绝保留在有界内存。之后每个 HTTP 请求先尝试刷新待写记录，未成功前不进入业务 handler，包括 `/health`。恢复后只刷新审计，不重新执行之前拒绝的操作。
- 未写入记录在进程退出时仍可能丢失；持续故障或超过 1000 条同样可能淘汰记录。响应没有假称“已落盘”。这不是磁盘配额、无限期保留或归档系统；SQLite 文件高水位不等于当前保留条数。

既有 `authorization_audit` 的独立落盘和 503 `audit_persistence_failed` 语义保持不变；若随后请求审计也无法写入，外层明确返回 `request_audit_persistence_failed`。备份整个 SQLite 数据库会包含新增表。业务快照 schema 仍为 1，配置版本仍为 2；旧代码不会读取新请求表，回退不可声称仍有本功能。

## 开发入口的迟到认证补缝

原开发入口部分 POST 路由只在读取 body 之前认证。本次把所有实际读取 JSON 的开发路由统一到 `readBody()`，在 await 后重验同一身份，拒绝读取期间到期、撤销或身份映射变化的凭据。原先已有检查的路由保持该行为；不延长任何期限，也不改真实配置。私有入口既有 body／idle-poll 后重验同时比较认证返回的 actor 必须仍为初次 actor，修复原来 token 映射切换后仍闭包旧 actor 的漏洞；不切换新 actor 继续操作。

这修复的是开发入口既有漏洞，不表示新增登录、续期、远程部署或真实凭据管理。测试仅使用本机合成身份和临时 loopback 服务。

## 验证

新增 `test/request-audit.test.ts` 覆盖真实 HTTP 的认证／格式／冒用／授权／租约／协议失败、1000 条边界、SQLite 重启、业务回滚、落盘故障与恢复、未知路由／异常文本净化、畸形 request-target、响应已发送／断线、并发分段慢 body 和 idle long-poll 到期。开发慢 body 的八种路由分别验证到期与撤销，业务动作调用次数为零。
