# 成员生命周期：资源内移除

服务端支持在已有授权资源内移除成员，持久化移除记录，并使旧运行上下文失效。另有[显式创建群聊/私聊及初始权限接口](conversation-creation.md)。成员移除不新增身份、不授予权限，也没有重新加入或管理界面；群聊和私聊均须独立满足范围授权，不能由类型标签替代权限检查。

## 接口与权限

`GET /memberships?conversationId=…&threadId=…` 返回范围成员资料及成员关系 `revision`。`POST /memberships/remove` 接受 `conversationId`、`threadId`、`targetMemberId`、`expectedRevision` 与 `clientEventId`，返回变更回执和 `duplicate`。请求中的操作者身份只能来自认证凭据。

两项操作都要求目标范围的有效 `manage_resource`，按统一策略计算，默认拒绝且显式 deny 优先。管理者不必拥有 read；响应只含成员关系元数据，不包含消息、运行或私有内容。成员类型不影响规则，拥有同样 Grant 的人和 Agent 可以执行同样操作。管理操作不修改任何 Grant，`grant_permissions` 仍默认禁用。

同一操作者的相同 `clientEventId` 重试返回原变更；不同参数复用该标识、旧范围修订均返回冲突。每次重试仍需当前管理授权；若操作者移除了自己，其后续查询或重试也会被拒绝。HTTP 响应丢失不能据此推定操作未发生，应由仍获授权的管理者查询当前成员关系。

## 持久化和运行边界

移除记录存入已有 SQLite 状态事务，覆盖启动配置中的成员关系，不修改配置文件、身份资料或原始 Grant。普通重启不会让成员重新加入；事务保存失败会同时回滚成员关系、上下文和租约取消。旧快照缺少此覆盖层时保持原有成员关系。显式恢复较早备份仍会恢复当时的成员状态，不能声称撤销记录能跨任意历史回档保留；恢复操作的授权对账仍由备份流程负责。

鉴权、会话发现、成员列表和 Worker 调度均使用有效成员关系。移除只作用于指定范围，其他独立资源授权继续有效；身份及历史作者 ID 保留。现有 Grant 即使仍存在，也不能绕过已移除的范围成员关系。本切片没有重新加入入口，不会自动复活旧 Grant。

有效成员变更推进范围上下文版本，使旧运行及派生结果失效，并取消已有租约。已领取工作若因成员被移除无法上传有效停止回执，保持 unknown；不会授予临时读取权来接收回执。仍获授权的执行者可以按既有协议确认实际停止；未领取工作有明确未启动证据时才可标 stopped。成员变更不会自动重启研究，也不假定可以撤销已经发生的外部动作。

## 创建边界

现有授权只针对精确范围，没有隐式工作区父资源层级。任意线程上的管理权不能用于创建其他私有范围。动态群/私聊创建通过可选服务器配置明确授权范围、允许委托动作和期限，并绑定静态来源 Grant。创建者不自动获得读取或管理新资源的权利，私聊也不自动向双方授予 read/send。具体请求和来源失效语义见创建文档。

## 验证

`memberships.test.ts` 验证覆盖层、幂等、冲突和快照恢复；`private-memberships.test.ts` 通过真实 HTTP/SQLite 验证无阅读权的管理、隔离资源、角色类型等价、回滚、重启、旧租约和结果失效。浏览器回归验证当前讨论缓存清除、重新连接后持续失效，以及运行中 Agent 移除后的成员列表与 unknown 呈现。测试使用显式配置的临时身份，不修改真实权限或部署。
