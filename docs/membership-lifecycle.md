# 成员生命周期：加入、移除与重新加入

服务端支持已有授权资源内的成员移除，以及动态创建会话中的添加/重新加入；共享界面提供对应管理弹窗。另有[显式创建群聊/私聊及初始权限接口](conversation-creation.md)。成员关系不新增身份或隐含阅读权；群聊和私聊均须独立满足范围授权，不能由类型标签替代权限检查。

## 接口与权限

`GET /memberships?conversationId=…&threadId=…` 返回范围成员资料及成员关系 `revision`。`POST /memberships/remove` 接受 `conversationId`、`threadId`、`targetMemberId`、`expectedRevision` 与 `clientEventId`，返回变更回执和 `duplicate`。请求中的操作者身份只能来自认证凭据。

两项操作都要求目标范围的有效 `manage_resource`，按统一策略计算，默认拒绝且显式 deny 优先。管理者不必拥有 read；响应只含成员关系元数据，不包含消息、运行或私有内容。成员类型不影响规则，拥有同样 Grant 的人和 Agent 可以执行同样操作。管理操作不修改任何 Grant，`grant_permissions` 仍默认禁用。

同一操作者的相同 `clientEventId` 重试返回原变更；不同参数复用该标识、旧范围修订均返回冲突。每次重试仍需当前管理授权；若操作者移除了自己，其后续查询或重试也会被拒绝。HTTP 响应丢失不能据此推定操作未发生，应由仍获授权的管理者查询当前成员关系。

## 持久化和运行边界

移除记录存入已有 SQLite 状态事务，覆盖启动配置中的成员关系，不修改配置文件、身份资料或原始 Grant。普通重启不会让成员重新加入；事务保存失败会同时回滚成员关系、上下文和租约取消。旧快照缺少此覆盖层时保持原有成员关系。显式恢复较早备份仍会恢复当时的成员状态，不能声称撤销记录能跨任意历史回档保留；恢复操作的授权对账仍由备份流程负责。

鉴权、会话发现、成员列表和 Worker 调度均使用有效成员关系。移除只作用于指定范围，其他独立资源授权继续有效；身份及历史作者 ID 保留。现有 Grant 即使仍存在，也不能绕过已移除的范围成员关系。

## 添加及重新加入

`POST /memberships/add` 接受与 remove 相同的目标、范围、预期成员修订及请求 ID，另可选 `grant: {actions, expiresAt}`。要求目标范围 `manage_resource`；附带新 Grant 还要求原创建授权范围的静态 `manage_workspace` 和 `grant_permissions`，动作/期限沿用创建边界。没有 grant 只加入成员，不发放任何动作权限。候选身份必须已注册且当前属于原创建授权范围。已有活跃成员再次加入返回冲突，不把 add 当作权限更新接口。

仅动态会话支持 add；群聊可添加注册成员，双人私聊只允许恢复原始两位身份，不能添加第三人。试点最多保留 20 个历史成员身份。每个动态会话持久保存原始创建授权范围；PR26 旧快照只在已有初始 Grant 能唯一证明来源时迁移，无法确定来源的旧会话不猜测当前配置，拒绝添加操作。

加入事件和移除事件共同按范围修订重放，移除历史不会删除。每次加入产生新的成员版本；新 Grant 绑定该版本。旧静态 allow 和缺少版本的旧动态 Grant 仅对初始版本有效，不能在重新加入后恢复；静态 deny 对所有版本继续生效。当前代的授权、旧任务绑定、会话发现和回执读取共用这套规则。重新加入不恢复旧 Worker 租约、发布资格或管理权；旧的未确认执行仍可保持 unknown。

加入、成员版本、新 Grant、幂等回执、上下文失效和租约取消在同一事务中持久化，失败全部回滚。同一旧 add/remove 请求在成员后来重新加入后重放，只返回原回执，不重复授予或再次移除；冲突参数返回 409。加入后的明确 read 可读取普通消息历史；派生研究结果在受众改变时失效。该成员旧阅读位置清除，客户端按新成员版本替换缓存，不能沿用旧草稿。

消息发送、编辑、撤回和已读写入携带 `expectedMembershipGeneration`，取自 `/session` 的会话成员版本。服务端在当前动作授权后验证版本，迟到的旧代请求返回 `409 membership_generation_conflict`，不能借新 Grant 执行。缺省值仅兼容初始版本 `initial`；重新加入后调用方必须使用新的版本。读取历史和只读回执仍受当前 read 控制，不因版本变化转为隐式写入。

有效成员变更推进范围上下文版本，使旧运行及派生结果失效，并取消已有租约。已领取工作若因成员被移除无法上传有效停止回执，保持 unknown；不会授予临时读取权来接收回执。仍获授权的执行者可以按既有协议确认实际停止；未领取工作有明确未启动证据时才可标 stopped。成员变更不会自动重启研究，也不假定可以撤销已经发生的外部动作。

## 创建边界

现有授权只针对精确范围，没有隐式工作区父资源层级。任意线程上的管理权不能用于创建其他私有范围。动态群/私聊创建通过可选服务器配置明确授权范围、允许委托动作和期限，并绑定静态来源 Grant。创建者不自动获得读取或管理新资源的权利，私聊也不自动向双方授予 read/send。具体请求和来源失效语义见创建文档。

## 验证

`memberships.test.ts` 验证覆盖层、幂等、冲突和快照恢复；`private-memberships.test.ts` 通过真实 HTTP/SQLite 验证无阅读权的管理、隔离资源、角色类型等价、回滚、重启、旧租约和结果失效。浏览器回归验证当前讨论缓存清除、重新连接后持续失效，以及运行中 Agent 移除后的成员列表与 unknown 呈现。测试使用显式配置的临时身份，不修改真实权限或部署。
