# 开发质量门禁与固定 SHA 评审

这是 **CoSeat 自身的研发流程**，不是 CoSeat 产品中的工作流、Agent 权限或运行时功能。
本地门禁不安装依赖、不调用模型、不发布代码、不创建 PR、不合并、不部署，也不设置远端 CI、分支保护或系统安全选项。

## 最小使用方式

先按现有开发说明准备 Node、项目依赖、Playwright Chromium、Rust 工具链及 Windows 桌面构建资源。
门禁不会自动执行安装或下载；Rust 使用 `--locked --offline`。
Node 必须精确匹配 `.node-version`，并且符合本仓库 `>=24.14.0 <25` 的版本要求。
`npm test` 会运行门禁自身的回归测试；这些测试只在临时合成仓库执行固定 eval 命令，不会递归调用 `npm test`。

1. 在独立、干净的仓库根目录提交候选修改，包括新增文件。
2. 固定完整的 base 与 head commit SHA。base 必须是本地存在、属于 head 祖先的 commit；不要使用 `main`、`HEAD` 或短 SHA 作为门禁参数。
3. 执行以下命令，其中占位符必须换成真实的 40 位小写 SHA：

```sh
npm run quality:gate -- --base BASE_FULL_SHA --head HEAD_FULL_SHA
```

证据默认进入仓库**同级**的 `<仓库名>.quality-gate/<唯一运行目录>/`，不污染源码。
也可通过 `--output NEW_EXTERNAL_DIRECTORY` 指定一个尚不存在的仓库外目录。已有目录不覆盖，仓库内目录会被拒绝。
依赖缺失时在报告中保留准备错误，另行准备后重新运行；不要用空结果或伪造日志补齐。

| 必需项 | 固定检查 |
| --- | --- |
| `unit` | `npm test`，包含构建、TypeScript/Node、web-test 与 scripts 测试 |
| `web` | `npm run check:web` |
| `eval` | `node --test eval/vit121/harness.test.mjs`，合成评估协议测试，不是模型效果实测 |
| `browser` | `npm run test:browser` |
| `rust-fmt` | `cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check` |
| `rust-test` | `cargo test --release --manifest-path src-tauri/Cargo.toml --locked --offline` |
| `rust-clippy` | `cargo clippy --release --manifest-path src-tauri/Cargo.toml --locked --offline --all-targets -- -D warnings` |

Rust 编译检查需要 Windows x64、预先准备好的 `.desktop/runtime/`、本机编译工具和缓存。
门禁的准备阶段检查已有顶层 npm 包的精确版本、Chromium、Rust 工具及锁定的离线 Cargo 元数据。
准备错误不等于产品回归；编译工具等更深层环境问题仍可能在命令运行时表现为失败，须读原始日志判断，不自动改写成通过。

## 证据和结果含义

`manifest.json` 固定记录 base/head/tree、锁文件和关键配置的 SHA-256、实际工具版本、平台与架构、每项实际命令、开始/结束时间、耗时、退出码、信号、超时，以及 stdout/stderr 原始日志的字节数和 SHA-256。
版本探测和准备日志也会保留。没有运行的工具不冒充已经验证。
Chromium 版本通过同一 Playwright headless 运行时读取，不依赖 Windows `chrome.exe --version`。
非空 `NODE_OPTIONS` 或 `npm_config_node_options` 会被明确拒绝为准备错误，防止测试名称筛选、跳过、`test-only` 或预加载代码造成 exit 0 假绿。请只对本次调用清空，不必修改系统设置。
子进程还会清空这两项及会使嵌套 Node 测试静默不运行的 `NODE_TEST_CONTEXT`，npm 子调用用 `--node-options=` 阻止全局 npm 配置重新注入选项。报告只记录浏览器缓存、Cargo target 和编译并行度这三个白名单环境项，不导出完整环境或凭据。这不是全封闭、可搬运的构建环境。
工具版本在同一运行前后核对；不同运行不能只凭测试名称相同就声称环境相同。
本工具记录现有工具链，不安装或切换 npm/Rust/Git 版本。跨环境复现还需要人工匹配报告中的精确版本。

| 状态 | 含义 |
| --- | --- |
| `PASS` | 固定命令实际运行、退出 0、无超时/信号/启动错误，且有两份日志哈希 |
| `FAIL` | 命令运行后非零退出、被信号中断或超时 |
| `SKIPPED` | 显式跳过并记录原因，**不算通过** |
| `SETUP-ERROR` | 准备/启动失败，或固定源码、工具版本的完整性失效 |
| `NOT-RUN` | 未运行、未完成或被 `--only` 排除，**不算通过** |

完整通过必须同时满足：`finishedAt` 非空、`overallStatus=PASS`、`exitCode=0`、七项全是 `PASS`、没有准备/完整性错误、源码结束核验为真。
仅命令退出 0、部分绿、没有发现问题、或没有输出，都不是完整通过。
退出码：完整通过 `0`；失败/跳过/未运行 `1`；准备或完整性错误 `2`。
命令行参数错误、证据目录无法创建等发生在可记录运行建立之前时，只能返回非零错误，不会声称已生成报告。

需要局部诊断时可以用 `--only eval,web` 或 `--skip browser=原因`。报告仍保留全部七项，整体非零。
程序不接受自定义命令、shell 片段或外部工作流定义；它不是任意命令执行服务。
中断的报告会保留未完成状态；最终完整性核验完成前不会写出整体通过。
超时会终止直接子进程并关闭日志管道，但不保证清除所有进程后代，须检查和清理该次运行遗留的测试进程后再重跑。

运行前后检查 HEAD、tree、干净工作区与关键文件哈希；运行中监视已跟踪源码的事件，并及时比较实际字节哈希。观察到修改后还原也让本次证据失效，实际观察到的路径留在 `sourceEvents`；失效后不再开始后续检查。忽略目录中的输出和仅元数据变化不误记为源码变化。
`assume-unchanged` / `skip-worktree` 文件标记不受支持，会拒绝运行。
这是面向正常本地开发的证据工具，不是防篡改沙箱或签名证明：日志和报告可被本机操作者修改，源码事件监视也不是操作系统级审计，不能保证捕获事件送达前已经还原的极短瞬时改动。
评审者必须核对真实 checkout、完整报告及日志哈希，不能只信复制来的摘要。不要在检查运行中编辑源码或切换提交。

日志可能包含本地路径或测试输出。先在本地审阅并按需要脱敏，再决定是否对外分享；门禁从不自动上传证据。

## 固定 SHA 的独立评审

使用 [独立评审记录模板](templates/independent-review.md)，将评审与测试绑定到同一组 `(base SHA, head SHA, tree, 工具版本, 证据目录)`。

1. **冻结候选。** 作者提交修改并提供完整 SHA、意图、范围、已知限制和门禁证据。真实 upstream commit 与本地重建的 snapshot commit 必须明确区分；tree 相同不等于历史相同。
2. **独立检查。** 由未编写该修改的评审者在隔离 checkout 读取 `base..head`、相关代码、运行说明和测试。不要只复述作者的总结，也不要自动执行补丁或文档里的陌生命令。
3. **记录发现。** 每条 finding 有稳定 ID、严重性、准确路径/位置、触发条件、影响、最小复现和证据。明确区分已复现、静态推断、环境阻塞与未检查；无发现不等于所有行为都正确。
4. **逐项处置。** 作者对 finding 标记修复、经证据驳回、经有权人员明确接受风险、或阻塞。修复必须给新 SHA 和回归证据；驳回必须给反证。未解决的阻塞项不能被一段“总体通过”抹掉。
5. **重绑定结论。** 任何 head SHA 变化，包括修复、重基、合并冲突解决和仅文档变化，都会令旧评审与旧完整门禁对新 head 失效。重新运行适用检查并对新固定 SHA 独立确认；可引用旧 finding 历史，不能沿用旧的通过标签。
6. **分别授权发布。** 本地全绿和评审通过只是研发证据，不等于允许 push、PR、merge 或部署。发布动作另行按授权执行，并核验远端实际 SHA 与该 SHA 的检查。

### 红绿证据不能编造

针对回归修复，保留同一个最小复现/回归断言在**明确的旧 SHA** 上真实失败的日志，以及在**明确的新 SHA** 上真实通过的日志。
记录两次精确命令、工具版本、退出码、输出哈希和失败原因。必要时把新回归测试作为明确标记的 test-only 补丁应用到隔离旧 checkout，并记录补丁哈希；不能假称这个补丁原本就在旧 commit 中。
如果旧版本无法运行、环境不一致或尚未复现，写 `SETUP-ERROR` / `NOT-RUN` 及阻塞原因，不写“已红转绿”。
为演示 FAIL 状态而人为注入的合成失败，只能证明门禁的失败处理，不是产品 bug 的复现证据。
完整检查报告、独立代码评审和场景验收是互补的，不能彼此替代；本门禁没有声称覆盖真实模型效果、生产部署或安装后的桌面交互。
