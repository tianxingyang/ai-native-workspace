# ADR 0002：私有试用采用出站领取与单实例 SQLite

状态：待审阅的私有试用实现；未部署。日期：2026-11-02。

控制端需要适配小内存单实例，Worker 位于无法从云端主动连接的网络中。保留原开发入口，新增独立 private-mock 配置与服务，使执行端主动请求领取、续租、回传事件。没有消息中间件、Docker、第二 harness 或通用工作流。

持久化暂用 Node 24.14.0 内置 `node:sqlite`，无独立数据库进程或 native npm 安装脚本。官方该版本文档仍标为 Active development；同步 API 简化“授权、结果、回执、幂等键一起提交”，代价是每次提交会占用事件循环。[固定版本官方文档](https://github.com/nodejs/node/blob/v24.14.0/doc/api/sqlite.md)

试用以一个版本化、8 MiB 上限的 JSON 聚合快照事务持久化，WAL + FULL 同步，单连接排他锁。上限 5000 消息、1000 Run，最近 1000 条审计；容量达限拒绝写入，不自动丢弃业务事实。选择该形式是为了复用已验证的领域逻辑且避免引入第二套事实源，不代表长期数据库结构。负载、检索、归档和多实例事务应在真实需求明确后另行设计。

租约记录 member、Worker boot instance、run 和到期；工具同时校验 lease 与现有 Grant。租约到期只封锁和要求对账，不自动重派。发布回执与去重键持久化，事件重复上报幂等；未知第三方动作绝不通过“恢复”盲目重放。控制端重启对已领取工作要求原实例停止，新 Worker 没有内部 session 时不假装恢复。恢复备份另有显式模式，将 queued 也视为可能已有未知后果。

私有配置仅引用管理员提供的环境秘密，缺失／公开夹具身份拒绝启动。控制服务只监听回环，远端 Worker 必须用 HTTPS origin，TLS 与设备权限由部署管理员另行落实。应用授权、设备 OS 权限、外部服务 scope 仍独立。

验证分层：确定性函数与真实 HTTP/SQLite；真实 pi SDK＋模拟模型；两种本机双进程入口。真实设备、TLS 入口、2 GiB 压测、真实模型和外部动作未验证。详见[试用说明](../private-trial.md)。
