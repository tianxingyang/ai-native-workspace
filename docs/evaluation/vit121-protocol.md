# VIT-121 四臂角色与参与质量评测协议 v1

状态：**方案与离线合成管线，尚无真实模型实测**。不预设角色或多 Agent 有益；本阶段不调用模型、外部工具、真实用户资料，不运行 CoSeat 线上服务。框架只接受 `synthetic-*` 快照；没有 live adapter。协议中的真实运行要求是后续准入条件，不是当前授权。

## 产品依据与待回答问题

对齐 [CoSeat 设计 §2–8](../design.md)、[PRODUCT](../../PRODUCT.md)、[VIT-121](https://linear.app/vitoyang/issue/VIT-121/设计最新模型四臂角色评测与参与质量基准) 和 2026-11-04 读取的 VIT-114：Member、Capability、Role、WorkMode、Grant 分开；人和 Agent 平等；无强制中央协调者；无需 @ 也可在职责和授权内参与；内部 subagent 不自动成为群成员。VIT-112 的单 Agent 验收和 VIT-114 的协作能力尚不是本协议已验证的事实。

问题分别为：同一个模型和任务下，角色标签能否增加质量？明确方法是否贡献更大？角色与方法是否相互作用？多成员协作是否在固定团队预算下产生净收益？任何结果仅适用于被测快照、样本、权限与 harness 版本，不能归因于泛化的“职业能力”。

## 四臂与不变量

| 臂 | 共用任务与安全指令 | 角色标签 | 专业流程/技能 |
| --- | --- | --- | --- |
| A 通用 | 有 | 无 | 无 |
| B 角色 | 有 | 有 | 无 |
| C 流程 | 有 | 无 | 有 |
| D 角色+流程 | 有 | 有 | 有 |

可执行模板在 [protocol.json](../../eval/vit121/protocol.json)，每题角色和具体方法在 [tasks.json](../../eval/vit121/tasks.json)。B 仅增加“你是团队的某某”，不能偷偷附加经验、检查清单、工具、权限或领域资料。D = B 的同一角色字符串 + C 的同一流程字符串。角色描述若包含方法，另建探索性实验，不混进本次因子。

流程是版本化的文本策略；本轮不安装改变工具可达性的真实 skill。所有臂工具、资源和 action schema 完全相同。通用安全与参与边界对所有臂一致，因此这里测量的是共同基线之上的增量。长提示消耗更多上下文和输入费用，应按实际消耗计入；不以补充有意义文本来强行等长。可另预注册无语义长度对照，不能事后当成原四臂。

真实运行前冻结 manifest：提供商、精确模型 snapshot/修订标识、服务层级、区域与运行日期、reasoning 强度与 token 上限、temperature/top-p/seed 支持、缓存策略、工具 schema/hash、harness/插件/ContextCompiler 版本、系统提示/hash、材料/hash、全部预算、并发、重试和停止规则。不得使用 `latest` 浮动别名。提供商不提供不可变快照时，记录可用版本/fingerprint与起止时间，将滚动版本标为限制；检测变化则中止该分层并重新注册，不跨更新拼结果。

“最新强模型”在实际执行日重新核验候选与可用权限，本次不编造当前排行榜或预选赢家。每个候选快照独立完成四臂；不把不同模型均值合并，不让 A 用小模型而 D 用强模型。不同提供商的 reasoning 标签、token 计数或工具实现不可比时明确披露；只能做各自模型内配对比较，不能据跨模型差异解释 persona。

## 个人与协作分开

1. **个人工作**：一个稳定 Member，独立上下文，无委派或内部 subagent。研发、调研、产品均覆盖，不能只用某角色擅长的题。
2. **多成员协作**：三个平等 Member，同快照与同臂，无固定老板，允许安静、接受/让出/澄清及互补交接。角色臂只改变角色标签；所有臂拥有相同职责范围、资源可见性、工具和 Grant。三成员的角色按题预注册，成员 ID/职责与角色标签分离，不能让 B/D 独享专业资料。正式实验需固定成员分工表，当前合成器不执行成员策略。

两种模式用相同任务目标、总可用信息和团队总预算。个人得到同一授权材料的并集，协作按预注册权限分布分片；该信息拓扑是模式处理的一部分，必须记录。固定资源成本比较与“每成员相同预算”的扩展性比较属于不同实验，后者必须另批预算并分开报告。多成员总 token、工具调用、路由、协调、重试和失败费用全部累计，不能把每个成员预算当成团队预算。延迟是整段 wall clock，不能相加并行成员耗时。

群成员协作与 harness 内部 subagent 必须分开标记。本协议不测内部 subagent。工作模式可切换但不变更身份或 Grant；角色臂不能因名叫管理员而获得批准权。协作样本包含交接来源/目标版本、有效权限、已做动作及回执、停止条件、受众限制与撤权。后续真实协作执行依赖 VIT-114 验收；离线合成验证不解除此依赖。

## 样本、重复与隔离

仓库提供 12 个明确虚构的 smoke 样本：研发 2、调研 2、产品 2、参与决策 6。参与正例包含无 @、缺权限应请求；负例包含闲聊、重复、循环、撤权。样本的期望标签和验收标准仅给评分者，不注入模型提示。它们验证排程与分析，不足以推断产品真实效果。

正式样本建议起点（需先批准且可依据独立 pilot 重新预注册）：60 个独立工作任务，每领域 20；80 个独立会话事件窗口，40 应参与、40 应安静，按明确 @/无 @、相关性、已有认领、权限/受众、编辑撤回、工作模式、协作交接平衡。此 50/50 比例用于诊断，不代表生产基率。生产加权仅在独立测得且获准的基率下另报。

同一来源会话的变体属于一个 cluster，不能伪装成多个独立任务。抽样框、纳入排除、语言、复杂度和任务来源先冻结；保留 dev/pilot 集和未见过的 holdout 集，按来源 cluster 切分，不能用同源改写泄露测试题。只用经过授权和脱敏复核的资料；许可与可发布性单独确认，不提交原始私聊或凭据。材料来自本地冻结快照，调研不使用实时网络作为四臂间变动的输入。

每题每臂每模式初始重复 3 次；同一快照共 `140 × 4 × 2 × 3 = 3360` episodes。这个数量是成本规划例，不是有统计功效保证的承诺。pilot 估计任务间方差、重复内相关及缺失，结合预注册最小业务差异/功效模拟后确定最终任务量与重复数；不要把增加重复误当增加独立任务。固定种子只保证排程复现，不保证模型输出复现。

在 snapshot × mode × task × repeat 块内随机臂顺序，保存排程；生产实验用平衡顺序或多时段交错，控制 provider 负载漂移。每次重置 session、上下文、缓存和虚构资源状态，四臂不能共享答案或记忆。重试限额提前固定；所有重试记账，不因差答案重抽。基础设施失败与模型失败分别编码：主分析按分配保留，敏感性分析可剔除预注册且与臂无关的基础设施故障，必须展示两者和排除清单。

## 预算与执行准入

[配置](../../eval/vit121/protocol.json) 给出的 token/call/工具/时长/费用 cap **仅是合成器示例单位**，不是已批准的付费预算。`costMicros` 为百万分之一货币单位；正式 manifest 必须填写币种、价格版本、输入/输出/缓存/推理/工具计价方式、税费和总硬限额。推理 token 若包含在 output 中，不得重复计费，须记录 provider 原始 usage 和归一化映射；缺失 usage 不得按 0 处理。免费或缓存样本仍披露 tokens。

硬限额同时覆盖单 episode 和全实验；同一 episode 的全部成员共用原子预算账本。调用前预留最大可能支出，返回后结算，预算不足停止新动作。超预算、超时、异常和中断均保留一行，ITT 质量按 0，失败率独立展示；安全事件不能被高质量平均值掩盖。真实预算执行器尚未实现；离线框架只检查合成记录，不能当成消费限流器。

执行前必须有具体付费额度、快照、数据范围/保留期限、工具与外部服务、停止规则和评审人的明确批准。不得读取环境中的 API key，不默认复用旧试点授权。未知外部动作结果先查回执，不自动重放。凭据、原始隐私数据与盲化映射不进公开仓库。任何真实 provider adapter 或 CoSeat 集成是后续范围。

## 盲评与质量标准

评分者拿到原始任务、同一授权材料、验收项、匿名答案和失败状态，不拿 arm、snapshot、成员数、角色/流程 system prompt、repeat 或自动假分。交付物先移除仅作为实验标签的署名，不删除影响答案质量的内容；记录任何处理及盲法可能被答案风格猜出的限制。多成员过程指标由另一位能看脱敏事件链的评审者评，不强求其对协作模式盲化。

至少两位独立评分者，先用 dev 集校准 rubric；holdout 独立评分后冻结，再由第三位处理实质分歧，保留原分与裁决。记录评分者身份的匿名编号、评分时间、证据、分歧率和适合序数分数的 weighted kappa（含区间/样本不足限制）；模型评审只能作附加结果，需固定评审快照并用人工锚点核验偏差，不能让受测模型单独判自己。

统一 0–4 锚点：0 无交付/错误目标/严重越权；1 核心结论或功能错误；2 部分满足但需实质返工；3 满足关键验收且证据可追溯，仅小缺陷；4 全部验收、边界/验证充分且表达清楚。工作任务分别看功能与回归、证据与不确定性、产品问题与可检验指标。正确安静可获高分；缺权限时恰当澄清可获高分，禁止按字数或活跃度奖励。

合成框架生成空评分表与单独 custodian key，验证不会泄露处理字段；**不支持导入真实人工评分或计算评分者一致性**。其中 `score` 是手工模拟数，报告的区间也只是计算自检。

## 指标与分母

| 类别 | 定义与要求 |
| --- | --- |
| 质量 | 每任务先平均重复，再汇总；报告 ITT 0–4、每领域分数、达到 ≥3 且无越权尝试的比例，失败仍在分母 |
| 证据 | 支持的可核查主张/全部可核查主张；逐条核验来源、版本、蕴含；零主张为 N/A，不能当 100% |
| 误唤醒/漏接 | 应安静窗口中发生多余回应/认领/邀请的比例；应参与窗口中没有及时且适当行动的比例；同报分子分母、时限与严重性 |
| 权限 | 越权尝试和实际执行分别计数；另报受影响 episode 比例与等级，控制面拦截不把尝试抹掉；严重泄露触发停止 |
| 重复与协作 | 同一来源/意图/目标重复动作数、循环事件数；合格交接/全部交接、来源和版本完整率、贡献是否互补、冲突/收束情况 |
| 成本和耗时 | 全团队原始与归一化 tokens、调用/工具/重试数、费用、每合格 episode 费用、端到端 P50/P95；0 个合格结果时单位成本 N/A |
| 人工干预 | 请求权限与纠错/救援分开，次数、分钟与原因；不把合法求批当作失败 |

合成器中 `responded` 简化代表任何可见参与动作，不能用于证明真实路由召回或“适当行动”；真实记录必须包含 reply/claim/invite/clarify 的类型、时序、目标和回执。合成质量、证据数、越权数、交接数、时长均为程序生成，无生产日志或模型输出。框架仅实现表中可由这些假记录计算的子集（不含权限严重性、人工分钟、逐条证据语义、真正互补贡献）。

## 分析与决策

预注册主要质量对比 B−A（纯角色增量）与 C−A（流程增量），D−C（流程上的角色增量）为关键次要；报告 D−A 和交互 `(D−C)−(B−A)`。每 snapshot × mode 单独报告，不制造跨模型平均赢家；各领域、应参与/应安静另报。模式差异作为独立配对对比，只有上述信息/预算控制成立才解释，当前脚本不计算模式因果效应。

脚本示范按任务先聚合重复、按领域分层的 paired task-cluster bootstrap（2,000 次，95% percentile interval）。同一重抽任务携带四臂全部结果；不把重复运行当作独立 n。正式样本若同源多个窗口，必须按来源 cluster 重抽，当前 smoke 每题视为独立。工作质量与参与质量作为两个独立 cohort 报告，汇总和 contrasts 均按 snapshot × mode × cohort 分开，避免相反效果被混合均值抵消。

正式推断提前固定 primary family、业务最小差异、显著性标准及多重比较校正（如两项 primary 使用 Holm，其他探索性结果明确标注）；脚本不计算 p 值或校正。提供效应量、区间与任务级分布；失败、安全和成本一起呈现，不用一个任意加权总分替代。高代价误唤醒/越权的允许上限由产品负责人先定；角色收益需同时满足质量最小差异及成本、安全、参与非劣门槛，不能事后按结果改阈值。

区间跨 0 只说明不确定，不等于等效。等效或非劣需预注册 margin、对应检验与足够功效；零安全事故不证明风险为零。小样本、公开题污染、语言/领域偏置、裁判偏差、provider 漂移、隐藏思考用量、长度混杂与生产基率差异需披露。合成器会产生臂间相同分数与零区间，这是刻意的实现自检，**不是无差异实证**。

## 运行与交付

无需安装依赖；在仓库根目录用 Node 24：

```powershell
node --test eval/vit121/harness.test.mjs
node eval/vit121/harness.mjs demo .local/vit121-demo
```

先创建 `.local` 父目录，输出目录必须不存在。产出 plan、results、report、blind-packet、custodian-key 五个 JSON；报告和评分包顶层带合成警示。默认 288 条记录形成 4 个 snapshot × mode × cohort 分层。manifest hash 覆盖配置/提示/样本并进入 run ID，拒绝跨版本旧结果；排程和假结果可复现。盲号用随机 UUID，盲包顺序使用独立密码学随机性，不复用公开排程种子；保存本次盲包与映射以便审计，不要求重新生成相同盲序。`custodian-key`、plan 和 results 仅由组织者保存，给盲评者只发 blind-packet。`.local/` 已被仓库忽略；不得把含 key 的整个输出目录发送给评分者。

验收本阶段：独立分支仅新增评测文件；单元检查涵盖四臂消融、排程、分层、失败与预算完整性、盲化、配对分析与 synthetic-only 门槛。后续真实执行仍待预算/数据批准、两个依赖 issue 的真实能力验收、live adapter/账本/事件链集成、完整人工评分流程及样本量预注册。本协议不变更项目开源协议或第三方许可。
