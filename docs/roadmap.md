# 阶段规划

状态：规划，不是已完成清单或开发、部署、付费评测已启动的声明。阶段按依赖推进，日期与预算待确定。内部开发跟踪使用 Linear，不在 GitHub 重复建立任务账本。

## M0 — IM 与可信控制基础

### 前置决策与可行性门槛

并行跟踪名称核查，不阻塞 IM 基础工程；明确项目许可证与上游组件使用方式；固定候选版本并验证 runtime 窄接口、隐式行为及 Worker 隔离可行性。确认首批预授权动作和风险边界。候选不满足最低契约时换方案，不把适配缺口留给提示词补救。

### IM 与统一成员基础

私聊、群聊、线程、成员、附件、消息持久化、实时投递与重连补发；Member / Capability / Role / Grant 分离；编辑撤回事件模型与最小 Context Compiler 契约；受控消息发送与后台状态分离。

**退出条件：** 身份稳定，重复投递不重复显示/处理；不可见内容不进入收件队列；人和 Agent 的越权请求都能被拒绝；具备授权与撤权检查、事件去重、基本审计等最低边界。模拟身份可预检，不能据此宣称真实多人安全。

## M1 — 无 @ 的单 Agent 工作闭环

以已获低风险只读权限的研究 Agent 验证无 @ 参与、相关性筛选、原子认领、后台执行与原线程反馈。以 pi 为首个 PoC，验证适配契约和工具网关；同时实现最小 Context Compiler、编辑撤回对在途工作的版本化生效、基本取消、重启、幂等与回执；退群或撤权须使已加载上下文失效并阻断旧输出，基础因果链与预算防止自唤醒，不能留待后续补安全。

**退出条件：** 相关讨论能自主触发、闲聊不乱接；不用手建工单；修改要求的实际生效可证明；取消与重启不导致未授权或重复动作；旧版本结果不能误发布；运行时隐式行为与控制能力缺口有明确记录。

## M2 — 平等协作与分域记忆

增加多 Agent 互补协作、审批/代执行、拒绝与超时、交接与防循环；扩展 M0/M1 已建立的最小 Context Compiler，加入分域召回、Memory Gateway 与可替换记忆后端。保留个人、群、项目和任务资料边界，覆盖删除传播与权限内数据导出。WorkMode 支持切换，不固定为五个 Agent。

**退出条件：** 两名真实用户与三个 Agent 的群聊验收通过：无 @ 自主参与、互补认领、改目标、探索转建设、无权审批/发布被拒绝、审批不可达保持阻塞、私聊隔离、退群撤权使已加载上下文失效、取消重启无重复副作用、精简不越权删除、成果回原线程且协作能收束。

## M3 — 可替换运行时与扩展验证

增加第二 runtime，验证跨运行时交接；注入长等待、外部回执缺失、旧 Worker 复活和备份恢复故障；建立锁版本升级回归。先完成按具体最新可用模型的角色/专业流程四臂评测方案，仅在预算及数据范围另行确认后执行，形成质量、实际成本与人工干预基线。

**退出条件：** 更换 runtime 不丢来源与授权，只有控制面决定恢复；未知外部结果先核对；删除/撤销不会因恢复重新泄露；关键质量与成本差异有可复核证据。外部工作系统集成另行确定范围。

## 跨阶段验证原则

- 在明确的验收集中，未授权动作、跨会话泄露、旧结果误发布、重复副作用和不可收束循环须为零；通过测试不代表全面安全保证。
- 记录消息/指令版本、Grant、审批、contextRevision、动作与回执，不能只展示模型输出截图。
- 同时记录误唤醒、漏接、首次有用反馈、交付质量、恢复时间、调用与实际费用；阈值由基线确定，不预设无依据的数字。
- 名称、许可证、runtime、记忆后端、权限策略与部署方式的决定分开记录；一个决定不自动批准其他事项。
