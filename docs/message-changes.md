# 消息编辑与撤回

当前增量允许成员编辑、撤回自己发送的普通聊天消息。两项操作都要求当前有效的 read 和 send 授权；取消任务仍独立要求 read + cancel。研究结果不能通过消息编辑接口改写，其他成员也不能改写作者的消息。

浏览器和 Windows 请求桥使用同一服务端接口：

```text
POST /messages/:messageId/edit
{ "expectedRevision": 1, "clientEventId": "unique-change-id", "text": "新的要求" }

POST /messages/:messageId/retract
{ "expectedRevision": 1, "clientEventId": "unique-change-id" }
```

服务端按作者和请求 ID 去重；同一请求 ID 更换参数、消息版本过期或消息已经撤回均返回 409。网络结果不确定时，界面使用原 ID 和原参数重试；版本冲突要求重新打开最新消息。每次成功变更产生不含原正文的不可变事件元数据，私有服务将消息、变更、上下文版本和取消意图一起保存到 SQLite。旧快照缺少新增集合时按初始版本读取。

## 旧上下文与停止证据

目前研究会读取整条线程，因此编辑或撤回会提升整条线程的 contextRevision，使该线程已有非终态运行失效。旧运行的读、工具调用和发布立即被门禁拒绝，并请求协作取消。其他线程不受影响。

没有创建 session 或发放租约时，可确认未开始；已发放租约则必须等待原执行实例确认。失联、租约到期、控制服务重启或无法确认停止时保留 unknown，不把取消受理等同于实际停止。已接受的新调研消息保留在队列，等待旧运行结束，不能被静默丢弃。

运行时当前不支持热更新。旧运行确认结束后，仍适用的活动调研会重新检查授权、重新绑定当前消息和上下文版本，并创建新的 run/session，通过 replacementRunId 关联旧运行。新输入已收到、待应用和实际 input_applied 证据分别显示；只有提供方确认应用后才显示“修改已应用”。主动取消的工作不会被编辑重新激活；撤回的源消息不重建。已经完成的研究只标记失效，不因后来编辑自动重跑。

## 可见内容与剩余范围

普通消息读取不返回撤回正文。旧线程结果失效后移除其可见正文和来源；发布回执保留，表示它曾经发布。运行列表与详情也过滤失效上下文的事件内容，防止通过 output/assistant 事件再次读取旧正文。内部事件账本保持原样，以便原 Worker 幂等重放；这不是物理数据擦除，也不能撤销已完成的外部动作。

本增量不完成整个 VIT-109：退群和在线撤权的管理 API、独立目标修改模型、搜索索引/长期摘要的删除传播、真正的模型服务及跨设备部署验收仍待完成。既有权限修订、失效和发布门禁继续生效；此次不调整真实授权、网络或部署。

## 验证

后端回归覆盖作者与 read/send 权限、并发版本冲突、响应丢失后的幂等重试、整线程上下文失效、迟到结果、创建 session 时编辑、停止窗口新消息、持久化重启、unknown 和已发布内容的投影过滤。浏览器回归覆盖编辑/撤回、同 ID 重试、跨设备版本冲突、撤权后清空编辑框及既有 IM/通知流程。桌面桥白名单包含 edit/retract，仍拒绝任意 URL、路径穿越与未知操作。
