# 逐范围增量同步

共享 IM 客户端使用 `GET /sync?conversationId=…&threadId=…&cursor=…` 获取消息、公开运行状态和本人阅读位置。每次请求独立认证并校验该范围阅读授权；游标不授予权限。已有 `/messages`、`/runs` 和 Worker 接口继续可用。

## 响应与合并

- `streamId` 标识范围索引实例；`cursor` 是客户端应原样保存的不透明位置，绑定认证成员和范围。
- `reset: true` 时，`messages` 与 `runs` 是当前完整基线，应替换本地集合；否则仅包含变化实体的当前值，按 ID 更新或追加，并应用 `removedMessageIds`、`removedRunIds`。
- 每次均返回 `readThroughMessageId`，只代表本人阅读位置；它不要求消息或任务发生变化。
- 没有游标、索引实例已改变、位置已压缩或位置超前都会返回完整基线。`cursorAhead` 标记同一实例中的超前位置。格式错误或跨身份/范围游标返回 400；无阅读授权先返回 403。

客户端同时提交实体变更与新游标。成功发送、修改或取消会使该范围旧请求失效，下一次读取重建基线，避免迟到响应覆盖已确认操作。身份改变、范围被清除或阅读期限到期后也不能应用迟到响应。401/403 的处理先于旧内容丢弃；后台范围收到阅读拒绝时立即清除其缓存，即使同批次其他内容已经过时。

索引实例变化或位置超前会清除客户端旧阅读推进意图与本页已见标记，然后使用服务端阅读位置重建。已失效的阅读回调不能恢复旧目标。浏览器将基线与游标一起加密保存；刷新后在认证及逐范围同步成功前保持隔离，绝不先显示旧正文。

## 持久化与恢复

服务端在读取时对当前消息和公开运行投影计算哈希，按变化记录实体类型、ID 和序号；每个范围最多保留 512 条变更描述，不存历史正文或运行输出。压缩掉的游标自动回退到完整基线。一次离线期间的多次编辑可以合并为一个当前实体，撤回文本和失效结果不会作为历史事件重新发送。

私有服务将索引和业务状态在同一个 SQLite 聚合事务中保存后才响应；保存失败回滚索引，重试仍可取得变化。普通进程重启保留流标识与游标。显式备份恢复轮换所有流标识，旧版本快照缺少索引时创建新流，客户端据此重建。

游标中的成员/范围摘要仅防止误用，并非签名或认证机制。索引是最新状态同步基础，不保证每个中间事件逐个投递，不是设备送达回执或服务端已读确认；客户端同步不提供跨设备凭据同步；发送 outbox 使用独立的存储模块和协议。现有周期轮询和每范围当前状态扫描也仍存在，未承诺大规模消息吞吐。

## 验证

`test/delivery.test.ts` 覆盖重复游标、当前值投影、移除、压缩边界与错误输入；私有服务测试覆盖重启、备份恢复、旧快照、授权、事务失败、运行失效和旧结果清除。`browser-test/sync.spec.mjs` 覆盖断线增量、发送/编辑/撤回的迟到响应、后台阅读拒绝和回档后的阅读目标重建。原生桥接仅允许 `GET /sync`，仍沿用固定本地目标和认证边界。

## 客户端检查点（VIT-127）

`web/sync-store.js` 在独立 IndexedDB `coseat-sync-v1` 保存每个认证身份/范围/成员代际的最新消息及公开运行投影、匹配的消费游标、流标识与本人已看过但未确认的固定阅读目标。不保存认证 token、恢复密钥、成员目录、下载的附件或任意草稿。本人阅读位置由每次 `/sync` 返回的当前服务器位置重建；消费游标不是已读，也不是 Agent 已评估、接单或完成状态。

复用 `/session` 已有的 `outboxKey` **仅作为内存密钥材料**，以同步存储专属域分离的 SHA-256 派生 AES-GCM 密钥与不可读槽位标识；不改写发送队列。现有服务端密钥已绑定凭据、成员、范围、成员代际和存储恢复 epoch。每次写入随机 IV，槽位、修订号、阅读重建代际和期限作为认证附加数据。正文、运行输出和阅读目标全部位于同一密文中，通过单个 IndexedDB 事务原子替换；先完成事务，再发送阅读推进请求。

恢复流程：认证 session → 解密但不放入可渲染集合 → 携旧游标请求当前 `/sync` → 成功后合并稳定 ID 和移除项 → 提交新检查点并渲染。离线或权限拒绝不会展示解密结果。损坏/跨范围游标的 400 会以无游标请求重建，并丢弃旧阅读目标；流变化和超前游标也丢弃旧阅读目标。压缩造成的完整基线仍可保留当前流中实际存在的已见目标。已确认本地操作使游标失效，但留下无游标检查点和固定阅读目标，重启后完整同步，避免以不匹配的游标恢复。

并发窗口通过修订号比较交换协调。冲突时只合并已经观察过的消息 ID，不混合基线与游标；同流重建会推进持久阅读代际，旧窗口必须丢弃原阅读目标并重新同步；目标在恢复后的当前消息集合中重验并选择最远位置。退出/失权写入不含正文的墓碑，阻止已打开窗口的迟到事务复活内容；新的认证连接可以从墓碑建立新基线。每条检查点最多 4 MiB，每库最多 100 个有效槽位；成功替换清理其他已过期槽位。存储失败保留内存状态、重试同步和保存，不在落盘失败时发送阅读推进；不承诺浏览器拒绝存储、磁盘写满或进程在提交前崩溃时的持久恢复。

权限边界：每次 session 和 sync 都重新检查当前权限；已知读权限/凭据期限在离线时仍清除页面与密文。成员换代、退出、401/403 会关闭旧实例并清理可定位槽位；页面刷新允许已经排队的加密提交完成，网络回调仍受身份和代际检查。未知撤权在下一次成功联系服务端前无法获知，但重启后从不离线展示缓存。崩溃、不可写存储、已轮换密钥的旧槽位、浏览器配置备份和文件系统快照可能留下不可解密密文；成功写入会回收过期槽位，这不是物理安全擦除保证。

### 桌面验收边界

共享界面的原生 `desktop_request` 桥接恢复路径有浏览器桥接测试，凭据始终留在宿主。**这不代表完整桌面进程重启已通过**：当前 Tauri 配置仍为 `incognito: true`，且每次宿主启动创建新的演示服务与凭据。该安装版无法跨进程保留同一会话的 IndexedDB 检查点。后续需在稳定服务/身份下设计原生受保护存储或明确浏览器配置持久化策略，并通过 VIT-124 验证；本变更不调整隐私窗口、不改发送队列、不声称完成这项验收。

新增 `browser-test/sync-store.spec.mjs` 验证真实 IndexedDB 的事务中断、完整旧/新状态、密文篡改、身份隔离、并发窗口、迟到加密和残留回收；`sync-recovery.spec.mjs` 覆盖刷新隔离、固定阅读目标、无游标检查点、压缩、损坏/超前游标、备份回档、权限/期限清理和桌面桥接。现有 `sync.spec.mjs` 继续覆盖迟到本地操作与后台拒绝。

PR #33 集成回归同时验证普通子线程拥有独立检查点和阅读目标、父会话撤权清除子线程密文、父会话成员换代后旧子线程目标不可恢复；创建线程弹窗期间的消息仍不自动推进阅读。线程权限与密钥绑定沿用主干实现。
