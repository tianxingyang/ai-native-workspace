# 拒绝审计与业务回滚验证（2026-11-03）

基于 PR #2 的 `c080a2faada1d688b684973a7b7d8a31cf8ec1cc`，修复[审查发现](https://github.com/tianxingyang/ai-native-workspace/pull/2#discussion_r4452359394)。未修改在线服务、其他 worktree、授权期限、凭据或配置版本。

先运行新增 HTTP 回归，确认旧实现把 read/send/cancel 三条拒绝记录恢复成空数组：1 项运行、1 项失败。修复后业务仍回滚，现有权限检查审计由同库独立 `authorization_audit` 表保存，重启优先读取该表；业务快照保持 schema 1。

另一个边界测试发现旧审计 resource 会引用整个消息对象，后续修改消息会污染审计并放大持久化体积。现改为只复制 conversation/thread ID，恢复旧审计时也投影到这些字段，不存消息正文。allowed 表示权限检查结果，不代表业务提交成功。

## 验证结果

Windows、Node 24.14.0、npm 11.9.0，仅合成身份和资料。

- `npm test`：TypeScript 构建通过，50/50 通过，0 失败、0 取消、0 跳过；约 15.88 秒。
- `npm run demo`、`npm run demo -- --pi-mock`：原开发入口双进程完成。
- `npm run demo:private`、`npm run demo:private -- --pi-mock`：私有双进程完成，回执持久化、无 Worker 入站端口，日志不含测试令牌。
- `git diff --check`：通过。

相对 44 项基线新增 6 项：

1. 实际 HTTP 拒绝读取、发送和取消后，业务状态不变；审计在内存、SQLite 与重启后保留。
2. 先修改消息、认领和租约，再遭授权拒绝：所有业务变更回滚，审计独立保留并限制为最近 1000 条。
3. 业务快照超出 8 MiB：业务回滚，但权限检查审计仍成功提交；重启可读取。
4. 注入审计存储失败：返回 503 `audit_persistence_failed`，业务不提交；审计保留在内存，存储恢复后的事务先刷新待写记录，重启保留。
5. 旧快照审计兼容恢复，去除多余消息字段，然后能与新拒绝记录一起独立保存。
6. 首次请求即遭拒绝、尚无业务快照时，审计仍能独立持久化并跨重启恢复。

原到期边界、租约、重复交付、取消、响应丢失、备份与真实 pi SDK＋模拟模型测试全部保留。没有真实模型或在线服务验证。

## 限制与运维影响

仍只保留最近 1000 条现有 `authorize()` 检查，不是全量 HTTP 审计系统。审计采用独立事务，增加一次小规模 SQLite 写入；未做目标设备负载测试。数据库离线备份包含独立表；旧代码不认识该表，回退可能忽略最近拒绝记录。

若审计自身 I/O 失败，无法保证记录已落盘：返回明确 503，当前进程保留有界待写记录；进程在恢复写盘前退出仍可能丢失这些记录。修复没有假称消除磁盘故障，也没有在审计失败时提交业务或重放外部动作。
