# CoSeat 设计摘要

状态：设计草案，更新于 2026-11-02，尚未实施或验收。已确定首个调研闭环、开源方向、分设备部署与运行时插件化；具体 harness、许可证和自主权限默认值仍待决定。本文不构成实际部署、权限授予或安全能力已落地的声明。

## 1. IM 是产品主体

打开产品首先看到私聊、群聊、线程、未读和成员，而非任务看板。任务、运行、审批和成果以源消息附近的卡片或次级抽屉呈现。项目只组织上下文和资源，不是聊天的前置条件。首版范围为文字、附件和线程，暂不包含音视频、复杂企业组织管理或开放 Agent 市场。

人与 Agent 都是稳定的 `Member`；模型或 runtime 更换不应改变其身份。Agent 可观察获准访问的群消息，自主决定安静、回应、认领或邀请协作。没有强制的中央协调 Agent。

首个闭环选择 **A：群聊相关讨论 → Agent 自主认领调研 → 后台研究 → 带来源和限制的结论回到原线程**。不要求先创建工单，不将代码编写、合并或部署纳入这一首个业务闭环。

## 2. 身份、职责与授权分开

| 对象 | 含义 | 不代表 |
| --- | --- | --- |
| Member | 团队成员；human/agent 区分执行方式 | 默认上下级或审批资格 |
| Capability | 模型、工具、skills 和执行条件形成的能力 | 拥有执行权限 |
| Role | 关注范围、责任和验收方法 | 固定职业能力边界或授权 |
| WorkMode | 当前工作的优化方向与交付重点 | 新成员身份、提权或发布资格 |
| Grant | 对动作、资源、范围、版本、期限的有效授权 | 群中一句请求即自动授权 |

工作模式可选、可切换、可兼任，不是五个固定 Agent，也不是必经流水线：

- **Prototyper / 探索**：假设、试验和未决问题。
- **Builder / 建设**：可用成果、验证和限制。
- **Sweeper / 精简**：简化理由、影响、回归和恢复办法。
- **Grower / 增长**：用户问题、指标与实验。
- **Maintainer / 维护**：运行风险、处置与预防。

这些模式是组织工作的方法，不是角色提示词提高模型能力的实证。普通方法调整无需逐步审批；改变目标或授权需要相应权限。探索结论不能因被多次复述就变成事实，原型未经约定验收不能成为正式交付；精简也不扩大删除权。

## 3. 从消息到有边界的自主工作

流程：可见性与订阅筛选 → 相关性判断 → 原子认领 → 权限检查 → 后台执行/协作 → 原线程反馈。

支持明确 @、职责相关主动参与、已有工作延续。先用轻量过滤减少无效模型调用，但不能退化成仅 @ 触发。认领按源事件、意图和目标范围区分，允许互补工作并行，避免多个成员重复执行同一动作。

协作邀请携带目标、来源、交付物、停止条件与可共享范围。接收者可接受、让出或澄清。因果链、去重、轮次/调用预算、冷却和终止标记共同限制互相唤醒；不以消息数量或所有 Agent 活跃为成功。

**消息状态与工作状态分离：** 送达、已读、已评估不等于接单或完成。后台工作有待授权、排队、执行中、阻塞、取消中、已取消、完成和失败等状态。一次模型调用结束不代表交付完成。

## 4. 权限与审批是共享规则

人和 Agent 都受同一授权检查约束。缺能力时找协作者；缺权限时找有批准权的成员，或由有执行权的成员代执行。执行权不自动包含授予他人权限的权力，交接不复制 Grant，申请也不等于获批。

审批绑定具体动作、参数摘要、资源、范围、版本和有效期；变化、过期、撤销或审批者失权后重新校验。代执行记录实际执行者及回执，不共享长期凭证或冒用身份。拒绝、超时或无人有权处理时保持阻塞，不自行升级。

修改目标、取消、恢复、批准与正式决定确认同样需要控制权限。模型只提出候选操作，不能把任意群消息当作控制命令。Agent 是否可担任特定审批者、高风险复核策略均待明确配置与验证；法律、平台或本人确认的硬边界不因此取消。

所有回复、协作邀请、审批卡片与成果发布都检查目标受众，不能为了求批泄露私聊资料。

### 4.1 两层权限与外部服务边界

- **CoSeat 应用权限**：成员可读的会话和资料、消息发送、认领/交接、审批及资源管理，由 CoSeat 服务端检查。人和 Agent 使用同一业务规则。
- **执行设备权限**：文件、进程、shell、网络和本机凭据，由该设备的操作系统、运行环境及管理员约束。CoSeat 群管理员身份不自动获得设备控制权；拥有本机 shell 也不自动获得 CoSeat 管理员权限。
- **外部服务权限**：GitHub 等服务的凭据 scope 决定技术可达范围，不等于当前任务已批准相应发布、修改或其他动作。工具存在不等于动作获准。

普通企业协作行为参考飞书的成员、资源 ACL 与审批模型，不让用户从零定义每个常规动作。但参考事实与 CoSeat 拟议默认值要分开：群历史可见性与文档授权分别建模；分享动作可能授予权限，应明确展示其效果；退群按授权来源重新计算，不能假设所有独立授权同时消失。Agent 的后台参与、跨会话记忆和已加载上下文撤权需要补充规则。具体默认值尚未确认，不把本节当成预授权。

自主范围先按获取信息、分析/执行、通信、修改/保存、组织工作、资源/承诺、身份/授权管理分类，再在每类中区分应用动作和设备动作，结合对象、受众、影响、预算与期限确定允许、需批准或禁止。

## 5. 单一控制面，插件化执行基座

### 5.1 分设备部署

CoSeat 服务端和数据库部署在一侧，Agent harness 与工作目录部署在独立执行设备上。执行设备通过受认证的 CoSeat API/消息协议参与协作，数据库仅由服务端访问。默认不向执行设备提供服务端 SSH、数据库、部署管理凭据或可写共享目录；若授予这些访问，必须重新评估隔离边界。该设计消除本机 shell 直接修改 CoSeat 数据库的路径，不把同机部署防护作为首版前提。

关系数据库保存事实，文件存储保存原始资料。自有控制面是成员、消息、可见性、任务/认领、Grant 与审批、决定及记忆来源、动作回执的权威。执行设备可以管理自身进程和运行检查点，但不能成为另一套团队身份、业务授权或组织记忆权威。

### 5.2 插件与适配器是同一个薄模块

借鉴 dsh 的插件化理念，而非把 dsh 选作必需依赖。每个 harness 对应一个运行时插件，其内部实现适配代码，不额外叠加两套框架：

- **CoSeat → Runtime 插件**：运行在执行设备侧，创建会话、提交输入、读取状态、回传事件、请求取消并报告实际停止情况。
- **Agent → CoSeat 工具**：让 Agent 以自身成员身份读消息、发消息、认领/交接任务、请求批准。可通过 MCP 或普通 API 接入，服务端执行应用授权。

插件不决定“哪条群消息值得参与”；参与策略独立于 harness 适配。CoSeat 的稳定 Agent 成员也不等于 harness 内临时创建的 subagent。内部委派可以用于执行一个成员的工作，不自动创建团队成员、授予权限或建立团队上下级关系。

最小拟定接口：

| 语义 | 首版要求 |
| --- | --- |
| 能力声明 | 声明版本及支持/受限/不支持的能力，不以空实现伪装支持 |
| 创建会话、提交输入 | 关联稳定成员、来源会话/线程、任务与运行；runtime session ID 不作成员或任务主键 |
| 状态与事件 | 输出、进度、待授权、完成/失败、取消结果；区分已收到和已应用 |
| 取消 | 请求受理与实际停止分开报告，记录仍可能进行或结果未知的动作 |
| 执行中追加输入、暂停、恢复 | 可选能力；按实际实现协商，不要求所有框架具有同名 API 或一致特性 |

工作包携带输入/上下文版本、有效授权范围、工具范围、预算与输出路由。检查点对 CoSeat 是绑定 provider、版本和会话的不透明引用，由原插件恢复；更换 harness 通过可解释的任务上下文和回执交接，不承诺跨 harness 原样恢复内部状态。

首版只做最小协议、一个插件和 CoSeat 工具集，再接第二个插件验证抽象。暂不建设插件市场、热加载/热更新或通用工作流引擎。

### 5.3 候选与需验证的行为

pi 与 Deep Agents 进入首轮候选，首个实现尚未确定；轻量可控性、首个闭环所需工程量与接口行为优先，不按功能数量宣布赢家。OpenCode、DeepSeek Harness（dsh）保留为适配候选；Hermes、OpenClaw 以机制参考为主，不默认嵌入完整助理产品。

Deep Agents SDK 可自托管，不要求采用其 CLI、托管服务或 LangSmith 云，但引入 LangChain/LangGraph 依赖和框架约定。2026-11-02 资料核查记录：Python 0.7.32、JS/TS 1.16.2，均为 MIT；两套版本独立，未逐项验证功能一致。公开文档为滚动版本，采用时需固定实际版本复核。这是候选记录，不是 CoSeat 的许可证决定或性能实测结果。

需要验证的具体差异包括：
- Deep Agents 的自定义 tools 是追加，不自动移除内置工具；需检查最终工具清单与 middleware 配置。
- 内置异步 subagents 需要兼容 Agent Protocol 的服务端，可自托管；不是单独引入 SDK 就获得完整后台调度。
- StateBackend、文件记忆和 runtime 摘要不能替代 CoSeat 的权限、来源和记忆治理，也不能据此宣布替代 OpenViking。
- runtime 审批/权限选项不是操作系统隔离；设备本地文件、网络、凭据和子进程停止由执行环境落实，不把这类规则全部塞进 CoSeat 成员 ACL。
- 扩展发现、资源加载、记忆注入、定时任务、自动重试和上下文压缩逐版本记录，防止与 CoSeat 边界冲突。pi 也有会话与持久化相关机制，不能以“完全没有恢复能力”作为比较前提。

## 6. 可靠执行与变更

消息与待发事件事务保存，按至少一次投递设计；游标补发、事件去重、原子 claim、租约、幂等键与 fencing 防止旧 Worker 或重复事件再次执行动作。不承诺跨外部系统的 exactly-once。

取消先阻断新动作与旧成果提交，再确认运行时/Worker 实际停止范围。取消请求已送达不等于已取消。外部动作结果未知时先核对，不盲目重放；已发生动作不能靠撤回消息或断开连接追回。

编辑、撤回和目标更新形成版本事件，明确“收到”和“已应用”的区别。旧版本迟到结果可保留受限历史，但不能按失效要求外发。重启和交接保存当前目标、有效授权、已执行动作与回执。

## 7. 记忆与最终上下文

自有事实库保存消息、授权、任务、决定与回执；派生记忆和检索索引可重建。OpenViking 是首个记忆后端验证候选，不作为最终事实权威，也不据此宣称已验证多租户安全。

个人、会话/项目、成员经验与任务工作记忆分别定域。经验不能藏入绕过来源权限的私人资料副本。每条候选记忆记录来源、版本、范围、确认与替代/撤销关系；假设、观察、推断与正式决定分层。

Context Compiler 先确定性装入有效授权、当前指令、取消/审批状态、决定、未决承诺和回执，再装任务原文，最后补充获准检索。硬约束不足或冲突时缩小范围或暂停，不能靠摘要静默丢掉。

Memory Gateway 对当前权限、来源和版本校验；检索路径或命中结果本身不是授权。退群、撤权、撤销资料和消息变更使受影响的已加载上下文失效；工具调用、回复及发布前再次检查，必要时停止并重建运行。删除索引不等于清除已加载内容，备份恢复也不得复活已撤销资料。

网页、仓库、邮件和检索文本均为不可信资料，其指令不能修改 Grant 或控制面规则。

## 8. 评测与未决项

角色提示的效果按具体最新可用模型快照分别验证，不用旧模型结论替代。计划四臂：任务本身、仅角色标签、仅专业流程/skills、角色加流程。控制思考强度、工具、输入与预算，分别报告质量、安全、误参与/漏接、重复工作、延迟、成本与干预，不能把未显著差异当作等效。

待明确：首批职责与分类后的自主权限默认值、审批策略、执行设备内部隔离细节、消息保留删除政策、IM 基础设施、首个 harness 及锁定版本、项目许可证、资源预算与指标阈值。开源方向与分设备部署不再是未决项；具体部署、权限配置和付费评测均未启动。
