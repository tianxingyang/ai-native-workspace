# CoSeat 设计摘要

状态：设计草案，尚未实施或验收。本文描述目标与约束，不构成选型、权限配置或安全能力已落地的声明。

## 1. IM 是产品主体

打开产品首先看到私聊、群聊、线程、未读和成员，而非任务看板。任务、运行、审批和成果以源消息附近的卡片或次级抽屉呈现。项目只组织上下文和资源，不是聊天的前置条件。首版范围为文字、附件和线程，暂不包含音视频、复杂企业组织管理或开放 Agent 市场。

人与 Agent 都是稳定的 `Member`；模型或 runtime 更换不应改变其身份。Agent 可观察获准访问的群消息，自主决定安静、回应、认领或邀请协作。没有强制的中央协调 Agent。

## 2. 身份、职责与授权分开

| 对象 | 含义 | 不代表 |
| --- | --- | --- |
| Member | 团队成员；human/agent 区分执行方式 | 默认上下级或审批资格 |
| Capability | 模型、工具、skills 和执行条件形成的能力 | 拥有执行权限 |
| Role | 关注范围、责任和验收方法 | 固定职业能力边界或授权 |
| WorkMode | 当前工作的优化方向与交付重点 | 新成员身份、提权或发布资格 |
| Grant | 对动作、资源、范围、版本、期限的有效授权 | 群中一句请求即自动授权 |

工作模式可选、可切换、可兼任，不是五个固定 Agent，也不是必经流水线：

- **Prototyper / 探索**：假设、试验和未决问题。
- **Builder / 建设**：可用成果、验证和限制。
- **Sweeper / 精简**：简化理由、影响、回归和恢复办法。
- **Grower / 增长**：用户问题、指标与实验。
- **Maintainer / 维护**：运行风险、处置与预防。

这些模式是组织工作的方法，不是角色提示词提高模型能力的实证。普通方法调整无需逐步审批；改变目标或授权需要相应权限。探索结论不能因被多次复述就变成事实，原型未经约定验收不能成为正式交付；精简也不扩大删除权。

## 3. 从消息到有边界的自主工作

流程：可见性与订阅筛选 → 相关性判断 → 原子认领 → 权限检查 → 后台执行/协作 → 原线程反馈。

支持明确 @、职责相关主动参与、已有工作延续。先用轻量过滤减少无效模型调用，但不能退化成仅 @ 触发。认领按源事件、意图和目标范围区分，允许互补工作并行，避免多个成员重复执行同一动作。

协作邀请携带目标、来源、交付物、停止条件与可共享范围。接收者可接受、让出或澄清。因果链、去重、轮次/调用预算、冷却和终止标记共同限制互相唤醒；不以消息数量或所有 Agent 活跃为成功。

**消息状态与工作状态分离：** 送达、已读、已评估不等于接单或完成。后台工作有待授权、排队、执行中、阻塞、取消中、已取消、完成和失败等状态。一次模型调用结束不代表交付完成。

## 4. 权限与审批是共享规则

人和 Agent 都受同一授权检查约束。缺能力时找协作者；缺权限时找有批准权的成员，或由有执行权的成员代执行。执行权不自动包含授予他人权限的权力，交接不复制 Grant，申请也不等于获批。

审批绑定具体动作、参数摘要、资源、范围、版本和有效期；变化、过期、撤销或审批者失权后重新校验。代执行记录实际执行者及回执，不共享长期凭证或冒用身份。拒绝、超时或无人有权处理时保持阻塞，不自行升级。

修改目标、取消、恢复、批准与正式决定确认同样需要控制权限。模型只提出候选操作，不能把任意群消息当作控制命令。Agent 是否可担任特定审批者、高风险复核策略均待明确配置与验证；法律、平台或本人确认的硬边界不因此取消。

所有回复、协作邀请、审批卡片与成果发布都检查目标受众，不能为了求批泄露私聊资料。

## 5. 单一控制面，轻量可替换 runtime

建议模块化单体与独立隔离 Worker 起步，关系数据库保存事实，文件存储保存原始资料。技术栈、版本和部署方式尚待验证。

自有控制面是以下信息的唯一权威：成员、消息及事件、可见性、任务/运行/认领、Grant 与审批、决定与记忆来源、最终上下文、副作用及回执。运行时只消费授权工作包，调用受控工具并报告事件，不能另起一套全局调度、记忆或恢复权威。

`pi` 是首个轻量 PoC 候选，尚未确认为最终选型或性能赢家。OpenCode、DeepSeek Harness（dsh）作为后续适配候选；Hermes、OpenClaw 以机制参考为主，不默认嵌入其完整产品及隐式控制面。

拟定适配契约为 `start / steer / cancel / status / events`，这是本产品需要的语义，不保证候选框架已有同名 API。先建立支持/受限/不支持矩阵。工作包绑定成员、源会话/线程、任务与运行、输入/上下文版本、Grant、工具清单、预算与输出路由。runtime session ID 不是成员或任务主键。

未经批准的扩展发现、资源加载、记忆注入、后台定时任务、自动重试和压缩行为必须逐版本审核。运行时内的工具审批不是操作系统沙箱；文件、网络、凭据和整个子进程树需要独立隔离。

## 6. 可靠执行与变更

消息与待发事件事务保存，按至少一次投递设计；游标补发、事件去重、原子 claim、租约、幂等键与 fencing 防止旧 Worker 或重复事件再次执行动作。不承诺跨外部系统的 exactly-once。

取消先阻断新动作与旧成果提交，再确认运行时/Worker 实际停止范围。取消请求已送达不等于已取消。外部动作结果未知时先核对，不盲目重放；已发生动作不能靠撤回消息或断开连接追回。

编辑、撤回和目标更新形成版本事件，明确“收到”和“已应用”的区别。旧版本迟到结果可保留受限历史，但不能按失效要求外发。重启和交接保存当前目标、有效授权、已执行动作与回执。

## 7. 记忆与最终上下文

自有事实库保存消息、授权、任务、决定与回执；派生记忆和检索索引可重建。OpenViking 是首个记忆后端验证候选，不作为最终事实权威，也不据此宣称已验证多租户安全。

个人、会话/项目、成员经验与任务工作记忆分别定域。经验不能藏入绕过来源权限的私人资料副本。每条候选记忆记录来源、版本、范围、确认与替代/撤销关系；假设、观察、推断与正式决定分层。

Context Compiler 先确定性装入有效授权、当前指令、取消/审批状态、决定、未决承诺和回执，再装任务原文，最后补充获准检索。硬约束不足或冲突时缩小范围或暂停，不能靠摘要静默丢掉。

Memory Gateway 对当前权限、来源和版本校验；检索路径或命中结果本身不是授权。退群、撤权、撤销资料和消息变更使受影响的已加载上下文失效；工具调用、回复及发布前再次检查，必要时停止并重建运行。删除索引不等于清除已加载内容，备份恢复也不得复活已撤销资料。

网页、仓库、邮件和检索文本均为不可信资料，其指令不能修改 Grant 或控制面规则。

## 8. 评测与未决项

角色提示的效果按具体最新可用模型快照分别验证，不用旧模型结论替代。计划四臂：任务本身、仅角色标签、仅专业流程/skills、角色加流程。控制思考强度、工具、输入与预算，分别报告质量、安全、误参与/漏接、重复工作、延迟、成本与干预，不能把未显著差异当作等效。

待明确：首批职责与预授权动作、审批策略、Worker 隔离、消息保留删除政策、IM 基础设施、候选版本及许可证、资源预算与指标阈值。上述评测仅为规划，尚未启动。
